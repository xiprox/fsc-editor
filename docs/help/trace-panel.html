The live field, and outcomes that are actually derivable

Fields are 112px now — room for 16256 or 1013.25 without clipping, which the slot has space for. current is drawn in --sim-value with a lamp on the right while it is being read; type in it and it goes to normal foreground and the lamp goes out.

On “the altimeter is set to…” — you are right, and I should not have written it

the altimeter is set to 1016 millibars requires knowing that A:KOHLSMAN SETTING MB:1 is an altimeter. Nothing in the model knows that. The SDK catalogue has a description — “Sets altimeter setting (Millibars * 16)” — but turning that into a sentence about what happened is generative, and this panel's whole contract is that every line is computed. It is also exactly how the card ended up serving ########### Pilot Lower Panel ######### as a description. The catalogue text has a home already: the hover.

So an outcome names variables and events, never aircraft systems. Below is what each shape can honestly end with.

Note what the result can and cannot say here. This is a shared: entry, so the string goes to the calculator whole and we do not evaluate RPN — so the honest ending is that the calculator receives it, not what the aircraft does. Slightly redundant with builds, and that redundancy is the truthful version.

The five endings the model can derive, and nothing beyond them: sent to the other pilot (with “unreliably” for master:) · the calculator runs code · EVENT fires with [args] · n is written to NAME, units, with “and EVENT never fires” when the fallback swallowed a named event · nothing is applied, with the reason.
